# Contributing to ZeteChat

Thanks for helping improve ZeteChat.

The project is in early development, so contributions should prioritize clarity, security, maintainability, and real user value over adding features quickly.

## Before contributing

- Check existing issues and pull requests before starting duplicate work.
- Keep changes focused. Avoid unrelated refactors in the same pull request.
- Do not add secrets, private credentials, customer data, or proprietary third-party material.
- Do not add fake metrics, testimonials, benchmarks, or unsupported claims.
- Explain material security, privacy, dependency, or infrastructure implications.

## Pull requests

A good pull request should include:

1. What changed
2. Why the change is needed
3. How it was tested
4. Any known limitations or follow-up work
5. Screenshots for meaningful UI changes, when relevant

Prefer small pull requests that can be reviewed safely.

## Code quality

As application code is introduced:

- Keep secrets and privileged operations on the server.
- Validate untrusted input.
- Enforce authorization server-side.
- Avoid unnecessary dependencies.
- Handle failures explicitly.
- Add or update tests for meaningful behavior changes.
- Keep accessibility in mind for interactive UI.

## AI-generated contributions

AI-assisted code is welcome, but contributors remain responsible for understanding, reviewing, testing, and licensing what they submit.

Do not submit generated code that has not been inspected.

## Conduct

Be respectful, specific, and constructive. Technical disagreement is welcome. Harassment, personal attacks, and discriminatory behavior are not.
